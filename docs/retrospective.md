# Ретроспектива командной разработки

## 1. Что планировали и что фактически завершили

В рамках проекта `star-bank-recommendation` команда реализовала основную функциональность и объединила изменения в ветви `main`.

Выполнено:

- Реализовано отдельное хранение динамических правил в PostgreSQL.
- Реализованы операции создания, получения и удаления динамических правил.
- Добавлена обработка динамических условий с поддержкой AND и negate.
- Динамические правила подключены к основному сервису рекомендаций.
- Добавлены кеширование и управление кешем.
- Реализована статистика срабатываний правил.
- Добавлены Telegram-бот и служебные endpoints.
- Подготовлены документы по архитектуре, требованиям, OpenAPI и развёртыванию.
- Изменения интегрированы через Pull Requests и объединены в `main`.
- Настроен CI для Pull Requests в `main` и `feature/recommendation-rules`; PR #33 успешно объединён.

По PR #25 итоговая зафиксированная проверка включала 34 теста без ошибок. В PR #33 зафиксировано 71 тест: 0 ошибок, 0 провалов, 2 пропущены; GitHub Actions завершился успешно.

## 2. Что помогало совместной работе

- Декомпозиция функциональности на отдельные Issues.
- Разработка в отдельных feature-ветвях.
- Интеграция изменений через Pull Requests.
- Автоматический запуск сборки и тестов в GitHub Actions.
- Использование общего репозитория и согласованных контрактов API.
- Содержательная проверка кода с исправлениями автора до принятия PR.

## 3. Что затрудняло работу

- Некоторые архитектурные решения и межмодульные контракты требовали дополнительного согласования в процессе разработки.
- Задачи с зависимостями между модулями требовали координации участников.
- Часть документации и командных артефактов оформлялась после реализации функциональности.
- Интеграционные тесты второй БД и конфигурация CI потребовали дополнительных исправлений.
- Настройки CI и обязательных проверок репозитория требовали отдельной проверки и фиксации.

## 4. Улучшения на следующий цикл

| Улучшение | Ответственный | Проверка результата |
|---|---|---|
| Согласовывать DTO, JSON-контракты и интерфейсы до параллельной разработки | Оба участника | Контракты зафиксированы до начала зависимых задач |
| Принимать архитектурные решения через ADR до реализации | Оба участника | ADR согласованы и имеют статус Accepted |

| Обновлять документацию одновременно с функциональностью | Автор соответствующего изменения | Документация соответствует актуальной реализации |

## 5. Итог

Основной функциональный цикл проекта завершён: отдельные модули реализованы, интегрированы, протестированы и объединены в основную ветвь.

Главные направления улучшения следующего цикла: раннее согласование межмодульных контрактов, формализация архитектурных решений, проверка CI для целевых ветвей и синхронное обновление документации.

Ретроспектива фиксирует результаты и предложения по улучшению. Она не означает, что все перечисленные улучшения уже внедрены.
